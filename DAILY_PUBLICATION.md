# Ежедневный финансовый кабинет

Опубликован: https://finance.academy-management.ru/cabinet#daily . Используется прежний вход и прежние роли owner/accountant/viewer. Права пользователей не менялись. Admin не получил нового доступа к финансовому кабинету. Ручной ввод сохранён по https://finance.academy-management.ru/?legacy=1 .

Вкладки кабинета: Обзор, ОПиУ, Деньги, Ежедневный отчёт. Месячная сверка остаётся датированным рабочим срезом; чистая прибыль октября не закрыта. Ежедневный отчёт имеет собственные дату и источник.

Автоматический источник: четыре ранее одобренных счёта Т-Банка (три рублёвых, включая овернайт, и евровый отдельно). ВТБ и другие организации не включены. Клиентские/внешние поступления не являются признанной выручкой; внешние списания не являются начисленными расходами. Явные возвраты — часть списаний, повторно не вычитаются. Свои переводы, тело депозитов и повторный перевод уже начисленных процентов исключены из внешнего потока. Рублёвые и евровые остатки не складываются.

Нарастающий итог — с первого числа выбранного месяца по последнюю проверенную дату включительно. Баланс — на последнюю дату, а не сумма дневных балансов. Отсутствующие дни ручного ввода не заполнены нулями. Автоматический календарный ноль допустим только после полной выписки и сверки. Источник бухгалтерии сохранён отдельно: до публикации 87 записей, последняя 08.10.2026; ноябрьской ручной истории нет.

Дополнительная сверка старой формы с новым сбором за 01–08.10: шесть внесённых остатков совпали с выписками с точностью прежнего ввода в целых рублях. Автоматический отчёт привязан к фактическим банковским датам, не к дате ручного ввода.

С 16.11.2026 обновление исполняется на сервере: systemd `finance-bank-sync.timer`, ежедневно 11:00 Europe/Moscow / 12:00 Asia/Dubai, с восстановлением пропущенного запуска после остановки сервера (`Persistent=true`). Таймер enabled/active; ближайший запуск подтверждён на 17.11.2026 08:00 UTC. Компьютер Андрея и открытый Codex не требуются. Прежняя автоматизация Codex `automation-3` переведена в PAUSED после успешного серверного цикла.

Серверная `finance-bank-sync.service` работает под отдельным пользователем financebank и вызывает только два ранее одобренных MCP-инструмента Т-Банка. Она собирает текущий месяц по вчера включительно; предыдущий дочитывается, если ещё не закрыт полностью. Код /opt/finance-bank-sync принадлежит root и недоступен для записи сборщику. Системная изоляция запрещает сборщику доступ к каталогу веб-приложения. Действующий ключ передан из DPAPI по SSH stdin прямо в systemd-creds encrypt, без открытых временных файлов, аргументов команд, Git или журналов. Зашифрованный файл /etc/credstore.encrypted/finance-bank-token доступен только root; ключ выдаётся только сборщику через LoadCredentialEncrypted. Веб-процесс ключ не читает. Шифрование привязано к серверному ключу; TPM на сервере нет. Полномочия банка не расширялись.

Локальная команда `pwsh -NoProfile -File scripts/sync_bank_report.ps1` сохранена для ручной диагностики и не запускается по расписанию. Прежний DPAPI-ключ сохранён для разрешённых локальных обращений. Не включать оба расписания одновременно.

Источник публикации — private/bank-daily.json. Серверный сборщик обрабатывает сырые операции только в памяти; на диске сохраняются дневные агрегаты и замаскированные счета без персональных назначений/контрагентов. Старые локальные выгрузки в local-state/bank-source/ и private/ исключены из Git.

После успешного сбора запускается отдельная finance-bank-publish.service без банковского ключа и сетевого доступа. Она повторно использует проверки publish_snapshot.py: четыре счёта, полный календарь и финансовые равенства; отвергает старый снимок и атомарно заменяет /opt/finance-dashboard/private/bank-daily.json. Предыдущая версия остаётся в bank-daily.previous.json. Временные файлы создаются с уникальными именами и безопасными дескрипторами. При ошибке последняя подтверждённая версия сохраняется. При 401/403, включая ошибку внутри MCP-ответа, создаётся постоянная блокировка /var/lib/finance-bank-sync/auth-blocked.json; новые обращения не выполняются до ручного исправления доступа. Состояние: /var/lib/finance-bank-sync/last-run.json, /opt/finance-dashboard/private/bank-sync-status.json, `journalctl -u finance-bank-sync -u finance-bank-publish`. Штатный sync не перезапускает веб-сервис, не меняет SQLite, пользователей, права, планы, 1С, DNS и не отправляет сообщения.
