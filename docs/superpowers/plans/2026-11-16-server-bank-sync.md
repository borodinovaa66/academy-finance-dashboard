# Серверное обновление банка

Поручение: перенести ежедневное обновление с Windows/Codex на действующий сервер. Расписание сохраняется11:00 Europe/Moscow. Полномочия банка прежние: четыре одобренных счёта, информация/операции, только чтение.

Решение: отдельный системный пользователь financebank без входа; systemd timer + oneshot. Действующий токен передаётся из DPAPI по защищённому SSH stdin непосредственно в systemd-creds encrypt, без вывода/локальных открытых копий. На Linux хранится encrypted credential; web-процесс financeapp ключ не читает. Служба читает лишь официальные MCP-методы с фиксированным endpoint/TLS/пределами и прежними проверками. Кандидат агрегатов атомарно публикуется отдельной root-службой без банковского ключа. Первичная SQLite и роли не меняются.

1. [x] Тесты запрета неподдерживаемых методов до чтения ключа, credential loader, извлечения ответа, server collector и сбоя с сохранением предыдущей версии.
2. [x] Отдельный transport/collector с повторным использованием проверенной математики bank_daily.py и publish_snapshot.py. Пакеты requests/jsonschema из ранее проверенного набора; банковский TLS bundle без изменения системного доверия.
3. [x] Загрузка кода и установка отдельного окружения; ограниченные systemd units, encrypted credential, права каталогов.
4. [x] Реальный запуск службы с проверкой числа операций/остатков и атомарной публикации; доказать, что web-процесс не читает ключ, а timer включён после перезапуска.
5. [x] Только после успеха остановить automation-3 Codex, обновить инструкции и журнал. Раскрыть пользователю только запрошенный действующий пароль сайта, не банковский токен. Пароль owner не сбрасывать по запросу «напомни».

Существующая worktree сохранена и чиста на старте. Старое расписание остаётся резервом до подтверждённого серверного запуска. Банк/права/платежи/1С/чужие сеансы не изменяются. При401/403 прекращать обращения до ручного решения; сетевые ошибки не приводят к публикации неполного снимка.
